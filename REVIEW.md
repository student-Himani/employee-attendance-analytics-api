# REVIEW.md

List every defect you found in the starter `app/main.py` (helpers and endpoints). For each one:

| # | Where (function / line) | What is wrong | How you'd notice it (test, input, or symptom) | How you fixed it |
|---|---|---|---|---|
| 1 | Startup / Lifespan | No database indexes were created at startup; only default `_id` existed. | Concurrent duplicate requests succeeded or failed unpredictably; queries on ~100k docs performed full collection scans (`COLLSCAN`). | Implemented `init_indexes()` called at startup creating unique index on `employees.emp_code`, compound unique on `attendance_logs.(emp_code, date)`, and compound query/analytics indexes. |
| 2 | `health()` | Returned `{"status": "ok"}` unconditionally without checking MongoDB connectivity. | When MongoDB was down or unreachable, `GET /health` returned HTTP 200 instead of HTTP 503. | Added `client.admin.command("ping")` within a try-except block, returning 503 on connection failure. |
| 3 | `EmployeeIn` / `create_employee()` | Missing `emp_code` regex validation (`^EMP\d{4,6}$`), allowed identical `shift_start` and `shift_end`, stored local naive time for `created_at`, and returned datetime object instead of epoch milliseconds. | `POST /employees` with `{"emp_code": "INVALID"}` or matching `shift_start: "09:30", shift_end: "09:30"` returned 201 instead of 422; response `created_at` failed schema validation. | Added Pydantic `Field` pattern constraints, model validator for distinct shift times, stored UTC datetime truncated to seconds, and serialized `created_at` to integer epoch milliseconds. |
| 4 | `create_employee()` | Check-then-insert race condition (`find_one` before `insert_one`). | Simultaneous concurrent POST requests with the same `emp_code` created duplicate records or raised unhandled 500 errors. | Relied on the database unique index on `emp_code` and caught `pymongo.errors.DuplicateKeyError` to return HTTP 409. |
| 5 | `list_employees()` | Incorrect skip formula `skip = page * page_size`. Since page is 1-indexed, page 1 skipped 20 items. | `GET /employees?page=1&page_size=20` returned an empty list `[]` when fewer than 20 employees existed. | Corrected skip formula to `(page - 1) * page_size`. |
| 6 | `list_employees()` | Total count used `count_documents({})`, ignoring the query filter (`department`). | `GET /employees?department=Engineering` returned total count of the entire collection rather than the filtered count. | Passed filter dictionary `q` to `count_documents(q)`. |
| 7 | `list_employees()` | Missing sort order and returned un-serialized BSON datetime for `created_at`. | Employees were returned in natural insertion order; `created_at` was not formatted as epoch milliseconds. | Added `.sort("emp_code", 1)` to the MongoDB query cursor and serialized `created_at` to integer epoch milliseconds. |
| 8 | `compute_late_minutes()` | Truncated minutes via `int(... / 60)` then evaluated `minutes > 10`. Also lacked IST date attribution and overnight shift awareness. | For shift 09:30, punch-in at 09:40:01 (601 seconds elapsed, `int(601/60)=10`) evaluated `10 > 10` as False, returning 0 instead of 10. | Rewrote helper to check `elapsed_seconds > 600` (strictly more than 10:00) against IST shift start, returning `elapsed_seconds // 60`. |
| 9 | `punch_in()` | Did not check if employee existed before accessing `emp["shift_start"]`. | `POST /attendance/punch-in` with non-existent `emp_code` threw `TypeError` resulting in HTTP 500 instead of HTTP 404. | Checked `if not emp: raise HTTPException(404, "Employee not found")`. |
| 10 | `punch_in()` | Relied on `find_one` before `insert_one` for duplicate checking, failing under concurrency. | Concurrent identical punch-in requests inserted duplicate documents or raised 500. | Relied on compound unique index `(emp_code, date)` and caught `DuplicateKeyError` to return HTTP 409. |
| 11 | `punch_in()` | Used server local datetime, ignored R1 whole-second truncation, and did not handle overnight shift date attribution (`shift_end <= shift_start`). | Overnight punch-ins before `shift_end` were attributed to current calendar day instead of previous day; timestamps had millisecond fractions. | Implemented `determine_attendance_date()` per R1, truncated instants to whole seconds, and converted to IST. |
| 12 | `PunchInIn` | Allowed arbitrary string for `status` (including `ABSENT` / `LEAVE`), and accepted seconds-looking timestamps (< 100,000,000,000). | `POST /attendance/punch-in` with `status: "ABSENT"` created invalid attendance record; seconds timestamps were accepted. | Constrained status to `Literal["PRESENT", "WFH", "ON_DUTY"]` and added `ge=100000000000, le=4102444800000` on `punched_at`. |
| 13 | `punch_in()` & `list_attendance()` | Injected `doc["id"] = str(res.inserted_id)`, violating `AttendanceRecord` schema; returned raw datetimes instead of epoch milliseconds. | Response contained unsupported `id` field and failed client schema validation. | Created `serialize_attendance_record()` removing `_id`/`id` and converting datetimes to epoch milliseconds. |
| 14 | `list_attendance()` | Loaded all documents into Python memory with `list(db.attendance_logs.find(q))`, sorting and paginating in Python. | Severe memory usage and query timeout when collection grew to ~100k records. | Offloaded filtering, `.sort([("date", -1), ("emp_code", 1)])`, `.skip()`, and `.limit()` directly into MongoDB. |
| 15 | `list_attendance()` | Missing parameter validation: did not reject `date_from > date_to`, and did not enforce `page_size <= 100`. | Querying `?date_from=2026-07-10&date_to=2026-07-01` returned HTTP 200 with empty list instead of HTTP 422. | Added validation raising HTTP 422 when `date_from > date_to`, and added FastAPI `Query(..., ge=1, le=100)` limits. |
| 16 | `compute_work_hours()` | Used Python's built-in `round(..., 2)` which applies banker's rounding (round-half-to-even). | Work hours ending in `.xx5` rounded to even numbers rather than half-up per R4. | Replaced with Decimal quantization using `ROUND_HALF_UP`. |
| 17 | `compute_overtime()` | Did not enforce the 30-minute minimum threshold (R3), and did not adjust shift end to next calendar day for overnight shifts. | 15 minutes of overtime returned 15 instead of 0; overnight shift overtime durations were computed incorrectly. | Enforced `minutes >= 30 else 0` and adjusted shift end date for overnight shifts (`shift_end <= shift_start`). |

### Items examined and decided NOT to be defects
1. **`load_dotenv()` behavior**: Examined whether loading `.env` would override actual environment variables provided by the test runner. `python-dotenv`'s `load_dotenv()` has `override=False` by default, so real system environment variables (`MONGO_URI`, `MONGO_DB`) properly take precedence over local `.env` files.
2. **`IST` timezone definition**: `IST = timezone(timedelta(hours=5, minutes=30))` is a constant +05:30 offset. Since Indian Standard Time does not observe Daylight Saving Time (DST), using Python's standard `timezone(timedelta(hours=5, minutes=30))` is fully accurate and avoids third-party timezone dependencies.
